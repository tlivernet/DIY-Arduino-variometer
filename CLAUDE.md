# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Two projects in one repository

**`vario-esp32/` — the active project.** A ground-up rewrite of the variometer on ESP32-S3: acceleration-compensated vario (Kalman filter fusing barometer and IMU), Sharp Memory LCD 400×240, BLE to XCTrack, PlatformIO build, 166 native tests. **This is where all new work goes.**

**`Variometer/Variometer.ino` — the historical AVR version.** A single 1131-line Arduino Nano sketch from 2014-2017 that only compiles on Arduino IDE 1.5-1.6.1. Kept unmodified as reference: its beep laws are what the rewrite's "Classic" tone profile must reproduce, and ten identified defects in it each have a named regression test in the new project. Vendored libraries under `libraries/` belong to it. **Do not modify it** unless explicitly asked.

Everything below concerns `vario-esp32/` unless stated.

## Commands

Run from `vario-esp32/`.

```bash
make test              # 166 native tests, 14 suites — the main gate
make test-test_kalman  # one suite
make render            # render screens to build/screens/*.png
make golden            # regenerate golden reference images (see warning below)
make hal-syntax        # syntax-check src/hal and src/app against Arduino stubs
make bom               # validate BOMs, generate distributor upload formats
make doctor            # report what dev tooling is installed
pio run -e esp32s3     # build firmware
pio run -e esp32s3 -t upload
pio device monitor     # serial console, 115200
mkdocs serve           # documentation preview
```

`make test` needs only `g++`, `make` and `python3` — Unity is vendored, and PBM→PNG conversion is pure Python.

## Architecture: pure core, thin periphery

This split is the load-bearing decision of the whole project. Respect it.

- **`src/core/`** and **`src/ui/`** are pure C++17. **No `Arduino.h`, no ESP-IDF, no globals touching hardware.** This is what makes the Kalman filter testable against synthetic trajectories and the screens testable against golden images, with no hardware at all.
- **`src/hal/`** and **`src/app/`** are thin adapters that inject a clock and sensor readings into the core.

If a change would put an Arduino include into `src/core/` or `src/ui/`, restructure instead: pass the value in.

### FreeRTOS core pinning

The Wi-Fi and BLE stacks live on core 0 and block interrupts there for long stretches. **All real-time work is pinned to core 1** (sensors prio 10, audio 9, display 5); radio work will go on core 0. Audio is generated by the LEDC peripheral, not in software, so a tone survives the cache stalls that flash writes impose on both cores. State is published through a length-1 overwrite queue: latest value, no blocking, no mutex.

I2C is shared between barometer and IMU, but only the sensor task touches it, so no lock is needed. Do not add I2C access from another task without adding a mutex.

`make hal-syntax` validates syntax against minimal Arduino/ESP-IDF stubs in `test/support/arduino_stubs/`. It catches typos and type errors. It does **not** validate build configuration or real IDF signatures — a C++11-vs-C++17 build failure slipped past it exactly for that reason. Keep the stubs mirroring the real header split; when they group things the real headers separate, they mask missing includes.

## Traps that cost real time

**`build_unflags = -std=gnu++11` in `platformio.ini` is mandatory.** The Arduino-ESP32 core appends its own `-std=gnu++11` after `build_flags`, and gcc's last `-std` wins. In C++11, a struct with default member initializers is not an aggregate, so every `ToneOutput{true, 690}` fails with an error that never mentions the language version. `core/clock.h` carries a `static_assert` that fires first with a message naming the fix.

**`-fno-fast-math -fno-finite-math-only` are mandatory too.** `-ffast-math` implies `-ffinite-math-only`, which lets the compiler treat `isnan()`/`isfinite()` as always false and **delete the guards** that protect the filter from a permanent NaN. That was defect #3 of the 2017 firmware; do not reintroduce it through an optimisation flag.

**Never run `make golden` to silence a failing render test.** Look at the actual output written to `build/*-obtenu.pbm` first, decide the layout change is intended, then regenerate.

**Nested-class default member initializers cannot be used in a default argument** in the enclosing class. `explicit Foo(const Config& c = Config{})` fails; use `Foo() = default;` plus `explicit Foo(const Config&)`. This has bitten four times in this codebase.

**Sharp LS027B7DH01:** CS is active **HIGH**, clock 1 MHz, and the bit order is subtle — pixel bytes go out as-is under MSB-first, but command and line-address bytes are numbers and must be reversed. Both are configurable in `SharpDisplay::Config`, with each wrong setting's symptom documented in `docs/mise-en-route.md`.

**IMU axis mapping is a mechanical choice.** A wrong sign gives a wrong attitude hence a wrong vario, and it is invisible on the ground. `Mpu6050::AxisMap` exists to fix it without rewiring.

**The partition table is sized for 4 MB flash.** Safe on larger parts but wastes the surplus. If targeting an 8 MB board, enlarge the LittleFS partition.

## Conventions

- `-Wall -Wextra -Werror` everywhere. It has already caught a real string-truncation risk.
- Monotonic time is `int64_t` microseconds (`vario::Micros`). The 2017 code stored `micros()` in a `float` and compared across its 71.6-minute wrap.
- Filter coefficients are time-based (`alpha = exp(-dt/tau)`), never per-iteration.
- **One test per historical defect**, named, with the defect explained in its comment. These are gravestones: they tell the reader why the code is shaped as it is. Do not delete them.
- Comments explain *why*, not *what*.
- Run `clang-format -i` before committing; the style gate is blocking in CI.

## Language

**User-facing strings, documentation and code comments are in French.** The project comes from the French free-flight community: the original menu labels, the README, the forum thread. `docs/` is French, `mkdocs.yml` sets `language: fr`. Keep it that way unless asked otherwise.

Commit messages and this file are in English.

## Prior art worth reading

- [GNUVario-E](https://prunkdump.github.io/GNUVario-TTGO-T5-website/) — French open source/open hardware vario, very close target: ESP32, e-paper, MS5611 + MPU9250, 3D case.
- [har-in-air/ESP8266_MPU9250_MS5611_VARIO](https://github.com/har-in-air/ESP8266_MPU9250_MS5611_VARIO) — zero-lag Kalman fusion, Wi-Fi config portal. Source of two decisions: MS5611 over BMP280 (the latter has disqualifying noise spikes), and a broadband piezo over a fixed-frequency buzzer.
